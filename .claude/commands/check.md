모든 HTML 파일을 점검하고 결과를 표로 보고한다.

## 점검 항목

1. **제목(title)**: 각 HTML 파일에 `<title>` 태그가 있고, 비어있지 않으며, 페이지 내용과 맞는 제목인지 확인한다.
2. **깨진 링크**: `<a href>`, `<img src>`, `<link href>`, `<script src>` 등이 가리키는 로컬 파일이 실제로 존재하는지 확인한다. 존재하지 않으면 깨진 링크로 표시한다.
3. **콘솔 에러**: 각 페이지를 브라우저로 열어 콘솔에 에러나 경고가 발생하는지 확인한다 (claude-in-chrome 스킬을 사용하거나, 로컬 서버 없이 파일을 직접 열어 확인할 수 있으면 그렇게 한다). 열어볼 수 없는 경우, 정적 분석으로 발견 가능한 명백한 JS 문법 오류만 표시하고 나머지는 "확인 불가"로 명시한다.

## 절차

1. 프로젝트 내 모든 `*.html` 파일을 찾는다.
2. 파일별로 위 3개 항목을 각각 점검한다.
3. 결과를 아래 형식의 표로 정리해서 보고한다. 항목별로 통과(✅) 또는 수정 필요(❌)로 표시하고, 수정 필요한 경우 구체적인 사유(파일:줄 번호, 어떤 링크가 깨졌는지, 어떤 에러 메시지인지)를 함께 적는다.

| 파일 | 제목 | 깨진 링크 | 콘솔 에러 | 비고 |
|---|---|---|---|---|
| index.html | ✅ | ✅ | ✅ | - |
| about.html | ❌ | ✅ | ❌ | title 태그 없음 / TypeError: ... (line 42) |

4. 표 아래에 수정이 필요한 항목들을 우선순위 없이 목록으로 요약한다. 실제 수정은 사용자가 요청하기 전까지는 하지 않는다.
